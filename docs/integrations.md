# Integration and credential register

**Status for every provider below:** adapter boundary **COMPLETED**; connectivity/permission **not verified**; live implementation **NOT STARTED**. Nothing in this repository initiates OAuth, refreshes a token, sends a message, calls an AI model, changes an ad, uploads a video, or creates a checkout. Account visibility is not approval to operate it. See `.env.example` for exact variable names. Blank entries are intentional. No real credentials, external account IDs or callback URLs have been assigned.

`src/integrations/registry.ts` separates provider capabilities, operations and disabled transports. Grant material belongs in an environment-specific encrypted vault; `integration_connections` stores owner, scopes, account reference, expiry, status and vault **reference** only. Inventory the named owner, approvals, last verification, rotation and revocation dates in the owner's secret manager. API request handlers never need management-plane credentials. ## Worker and callback contract (design, not running)

1. Provision stable environment-specific HTTPS URLs only **after** ownership/domain approval. Use official OAuth with registered redirect URIs, state, PKCE where supported, minimum scopes and per-account encrypted grants. Consent denied/expired → disconnected, not success.
2. Limit raw bytes and ingress rate; verify HMAC/signature before parsing or logging, compare in constant time where applicable, enforce provider timestamp tolerances and account allowlists. Challenge verification is distinct from event authenticity. Reject invalid events; never acknowledge unverified data as settled/delivered.
3. In one transaction insert `(connection_id,event_ref,body_sha256)` and a deduplicated job. Acknowledge after durable acceptance. Same ID/different digest → review; duplicate delivery → no repeat effects. Use a worker lease, bounded exponential backoff/jitter, attempt ceiling, `dead_letter` review and controlled replay.
4. Check consent, recipient, approved template/window, human approval and available budget again **at execution time**. Record sanitized outcome, provider/account-scoped ID, attempts and delivery state. Reconcile payments with server verification before invoices/access/receipts. No automatic advertising spend. No raw message bodies, secrets or student profiles in telemetry.
5. Separate dev/staging/prod projects, keys, merchant/sender accounts, budgets and rotation drills. Provider sandbox tests and client sign-off precede each live capability. A config value or connected external app is not an activation switch.

## Infrastructure prerequisites

GitHub: scoped repository access and reviewed PRs, protect `main`; CI requires only read access and no secrets. Supabase: approved project/ref and ownership, publishable key + URL and user auth for runtime; use a different identity for migrations. Service role is **not needed by this API**. Vercel: confirmed team/project/environment mapping, deployment rights only if approved; `VERCEL_DEPLOYMENT_TOKEN` is an inventory placeholder, not required locally. Domain/DNS: owner/registrar, TLS, email verification and strict redirect URLs. Do not bypass phone verification/MFA or borrow another owner's credentials.
