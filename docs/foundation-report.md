## What the checks do and do not establish

* Locally, two concurrent operators produced **one attendance row**. Reusing an identical request returned its prior result; reusing its key with different input failed. A revoked/replaced/expired card, unverified family link, wrong/inactive device or out-of-window scan did not create a new present mark. A manual correction retained its reason/actor/before/after and subsequent duplicate scans did not overwrite it.
* SQL tests use real PostgreSQL constraints, transactions, concurrency, role grants and RLS. They cover rollback without orphan guardians, foreign-family/teacher isolation, AAL1 denial even with two roles, consent withdrawal, private Storage object policy, provider event dedupe, import crosswalk integrity, CRM/CMS and personal notifications. A test drives the TypeScript HTTP handler through actual admission/issue/scan RPCs with test-only identity/transport substitutes.
* Transport tests cover Auth rejection, named RPC args, user JWT forwarding, denied origins, malformed/oversized requests, response validation, sanitized errors, quotas, URL signing and disabled webhooks. The Node deployment entry point was exercised over **local loopback**. The specification checksum and blank env template are checked. TOML/JSON configuration parses. `npm audit` reported no known dependency vulnerabilities at check time; this is not a security certification.
* No Docker/full Supabase stack, authorized staging runtime or Vercel deployment was used. Real Auth challenges/email/recovery, hosted PostgREST configuration, signed file retrieval/expiry, backups/restores, physical scans/printing, load, provider signatures/refresh/delivery and real migration reconciliation are **not passed tests**.
